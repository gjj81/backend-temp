# 销售计划-排产 状态规则说明（一般情况版）

> 适用范围：仅覆盖本期必选状态链与一般业务流转。取消、暂停、部分交付、作废回填等预留/突变场景不在本文档规则范围内。
> 对象层级：销售计划（PLAN）→ 产品行（LINE）→ 交货节点（NODE）；排产（SCH）挂靠产品行。

---

## 二、各状态规则（进来 / 出去 / 能做什么）

### 销售计划

**0 未下发 PLAN_DRAFT**
- 进来：① 新建计划，系统默认置 0；② 从 1 人工撤回 → 0。
- 出去：人工下发 → 1。
- 能做：编辑基础信息；增/删/追加产品行与交货节点；删除整单；下发。
- 守卫：删除产品行要求行=0；删除交货节点要求所属行=0。

**1 已下发 PLAN_ISSUED**
- 进来：从 0 人工下发 → 1。
- 出去：① 退回 → 0；② 归档 → 2。
- 能做：整单锁定——基础信息与已下发内容不可改、不可删除整单。白名单：计划未归档前均可追加产品行，只能生成新行（新行=0，需单独下发）。
- 守卫：退回要求全部产品行 ∈ {0}；只要下发有数据就不允许回退。

**2 已归档 PLAN_ARCHIVED（终态）**
- 进来：已下发的所有完成行满足订单量 + 人工点击归档（本期仅人工点击）。
- 出去：无（终态，不可流出）。
- 能做：只读；移出活跃列表，不进入默认查询。

### 产品行

**0 未下发 LINE_DRAFT**
- 进来：① 新增行默认 0；② 计划撤回级联打回 → 0；③ 行单独撤回 → 0。
- 出去：行下发 → 1（计划已下发时可单独下发；计划未下发时只能随计划一起下发）。
- 能做：随计划可编辑数量/日期；可删除（守卫：行=0）；不可排产。

**1 已下发未排产 LINE_ISSUED**
- 进来：人工下发 → 1（追加行单独下发，或随计划下发级联）。
- 出去：① 行撤回 → 0（单独撤回或计划撤回级联）；② 排产下发后系统回写 → 2。
- 能做：锁定——不可改、不可删除行、不可追加交货节点；★ 排产能力在此开放（可新增排产）；可撤回。
- 守卫：撤回要求该行下排产已全部撤销。

**2 已排产 LINE_SCHEDULED（派生）**
- 进来：该行下存在已下发排产 → 排产回写 → 2（从 1）。
- 出去：排产全部撤销 → 1；排产开工 → 3。
- 能做：可继续排产。
- 守卫：排产总量 ≥ 订单量（可大于/等于，不可小于）。

**3 生产中 LINE_PRODUCING（派生）**
- 进来：该行下排产开工 → 排产回写 → 3（从 2 或 4）。
- 出去：排产全部撤销 → 2（理论回退，生产发生后不会出现）；排产全部完工 → 4。
- 能做：可继续排产；填报作废经排产传导后回退。

**4 已完成 LINE_DONE（终态）**
- 进来：人工点击，前提是下面的排产全部完成。
- 出去：无（终态）。
- 能做：只读；纯终态，无任何可写字段。

### 交货节点

**0 未下发 NODE_DRAFT**
- 进来：① 新增节点默认 0；② 计划撤回 / 行撤回级联打回 → 0。
- 出去：计划下发级联或随行下发级联 → 1。
- 能做：★ 可编辑日期与数量；可删除（守卫：所属行=0）。

**1 已下发 NODE_ISSUED**
- 进来：计划下发级联 / 随行下发级联 → 1（从 0）。
- 出去：计划撤回级联打回 → 0（行撤回时同样级联 → 0）。
- 能做：★ 下发即锁定——只能查看，不可改、不可删。相当于规格（实际交货时间本期不设计）。

### 排产

**0 未下发 SCH_DRAFT**
- 进来：① 新增排产默认 0；② 从 1 撤销 → 0。
- 出去：人工下发 → 1（单条/批量）。
- 能做：计划员可见、车间不可见；可改日期/数量；可删除（无约束）。
- 守卫：必须与产品行联动——行未下发（行=0）时不允许新增排产；排产没有逻辑删除完，上面的销售计划不能被撤回。

**1 已下发未生产 SCH_ISSUED**
- 进来：人工下发（守卫：所属产品行 ∈ {1,2,3}）。
- 出去：① 撤销 → 0；② 车间点击「生产」或有填报数据 → 2。
- 能做：车间可见；不可编辑；车间只能做两件事：点击生产（→2）、撤销（→0）。
- 守卫：有数据不允许撤回到未下发状态。

**2 生产中 SCH_PRODUCING（派生）**
- 进来：车间点击「生产」或有填报数据 → 2（从 1）。
- 出去：完工 → 3（人工点击完工）。
- 能做：不可编辑；可填报产量。人工进入与填报进入均可。

**3 已完工 SCH_DONE（终态）**
- 进来：人工点击完工 → 3（从 2）。
- 出去：无（终态，不可流出）。
- 能做：全锁只读；下面不能再填报数据。想再动必须先作废对应填报降回——本期不处理（填报无状态）。

## 三、级联规则

### 1. 下发级联（人工，自上而下）

1. 计划 0→1 人工下发；
2. 级联：全部产品行 0→1；
3. 级联：全部交货节点 0→1；
4. 白名单：计划未归档（0/1 态）均可追加产品行 → 新行=0，单独下发（节点随行 0→1）；追加量由新行承载，不修改已有行。

### 2. 撤回级联（先守卫、后打回）

1. 行撤回守卫：该行排产已全部撤销；
2. 行 1→0（单独撤回 或 计划撤回级联）；
3. 节点级联打回：节点 1→0（行撤回、计划撤回均级联）；
4. 计划退回守卫：该计划下全部产品行 ∈ {0}（有下发数据就不允许回退）；
5. 计划 1→0。

### 3. 排产回写（系统，反向传导）

| 排产动作 | 产品行回写 |
|---|---|
| 排产下发（0→1） | 行 1→2 已排产 |
| 排产开工（1→2） | 行 2→3 生产中 |
| 排产全部完工（→3） | 行 3→4 已完成（配合人工点击生效） |
| 排产全部撤销 | 行 2→1；行 3→2（仅理论） |

### 4. 归档

全部完成行满足订单量 + 人工点击 → 计划 1→2 已归档（终态，只读，移出活跃列表）。

## 四、守卫规则汇总（硬约束）

| 编号 | 守卫 | 位置 |
|---|---|---|
| G1 | 删除产品行要求行=0 | 计划 0 / 行 0 |
| G2 | 删除交货节点要求所属行=0 | 行 0 / 节点 0 |
| G3 | 行=0 时不允许新增排产 | 排产新增入口 |
| G4 | 排产下发要求所属行 ∈ {1,2,3} | 排产 0→1 |
| G5 | 行撤回要求该行排产已全部撤销 | 行 1→0 |
| G6 | 计划退回要求全部行 ∈ {0}；有下发数据不允许回退 | 计划 1→0 |
| G7 | 排产总量 ≥ 订单量（可大于/等于，不可小于） | 行 ≥2 |
| G8 | 有填报数据不允许排产撤回到未下发 | 排产 1→0 |
| G9 | 排产未逻辑删除完，计划不能被撤回 | 计划 1→0（前置） |

## 五、守恒与口径说明

1. 「交货合计 = 订单量」为守恒校验；节点 4 已取消若启用，必须排除出该校验，否则校验永远对不上。
2. 排产 3 已完工为终态但本期不设「已结案」流出，作废填报降回本期不处理（填报无状态）。
3. 行 3→2 的回退仅为理论路径（生产发生后不会发生），实现可不预留。
4. 客户加量统一走「计划追加新行」承载：新行独立守恒（G7），不影响原行；行 4 为纯终态，无例外开口（原「调大订单量」规则已取消）。
5. 所有「预留」状态本期不定义进入/流出，只保留枚举占位，页面置灰不可达。
